# Switchyard V1: implementation plan

**Spec:** [PRODUCT.md](../PRODUCT.md) · **Architecture:** [ARCHITECTURE.md](../ARCHITECTURE.md) · **Last updated:** 2026-10-19

V1 must prove the thesis technically: a calibrated, deterministic floor twin whose incidents are explained by **replay-verified** post-mortems, with per-parcel traces and a chaos resilience score, all viewable in a browser. Visuals stay simple.

## Global constraints
- The determinism contract (ADR 0002) applies everywhere in `core`: integers only, no `HashMap`/`HashSet`, ChaCha8 streams per concern, single-threaded.
- 1 tick = 0.5 s; 1 cell = 1 m; one move per tick.
- The core crate is `switchyard-core`; the binary is `switchyard`.
- The Windows dev box uses the GNU toolchain, so no crates that need a C compiler.
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings` and `cargo test --workspace` are green before every merge.
- Each merge to `main` is a PR with test evidence; each session ends pushed, with `docs/STATUS.md` updated.

## Review focus (failure modes most likely to bite)
1. **Deadlock or livelock** under dense traffic or after a fault. The watchdog must surface it, not hang.
2. **Hidden non-determinism** (iteration order, a float sneaking in). The cross-platform hash job must catch it.
3. **Trace gaps or overlaps** after a robot fails while carrying a parcel. The property test covers it.
4. **Counterfactual confounding:** removing a fault shifts unrelated random draws. Per-concern streams prevent it; a test proves it.
5. **Throughput far outside 25–50 parcels/h per robot.** Calibration test bands.
