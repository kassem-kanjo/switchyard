# Switchyard V2: implementation plan

**Spec:** [PRODUCT.md](../PRODUCT.md) · **Design:** [design/v2.md](../design/v2.md) · **Research:** [2026-10-24-v2-design](../research/2026-10-24-v2-design.md) · **Last updated:** 2026-10-24

V1 proved the engine. V2 makes it **usable and convincing in minutes**:
- an ops leader understands an incident in **10 seconds**;
- a robotics engineer trusts the numbers in **60**;
- anyone can run it with **one download and one command**.

Visual direction: an operations console in the spirit of Palantir's products (see design §Layout). This is a layout change (three panes plus a timeline) on top of the token pass, built screen by screen against approved wireframes.

## Scope rules
- **No new engine algorithms.** V2 changes presentation, packaging and the launch. Engine changes are limited to the report's structure (the headline, folding, wording).
- **Determinism and the V1 gates still apply.** The insta snapshot and the planted suites must stay green, and any changed report line must be explained.
- **Visual changes go through `viewer/src/theme.ts` and `app.css` tokens**, never hard-coded colours.
- **Every number on screen comes from a real run** (global rule).
- **Budget:** about 3 working sessions for CP1 and CP2 together; the launch (CP3) is mostly Kassem's call.

## Success measures (checked at each gate)
| Measure | Target |
|---|---|
| 10-second test: a fresh reader (Sonnet, given only a screenshot of the panel) states the main cause, its share and the best fix | 3 of 3 correct |
| Time from download to the first post-mortem on screen | ≤ 2 minutes, one command |
| Report jargon | no bracket citations, ±-notation or game-theory terms above the fold |
| Phone legibility of video and cards | captions ≥ 40 px at 1080p; key numbers held ≥ 3 s |

**Goal:** a robotics company's engineer opens it and thinks "this is a real tool".

| CP2.3 (#34) | **First-run path.** The empty state offers one button: "Load an incident". It loads `two-dead-robots-and-a-jam`, plays to the dip, and opens the post-mortem. Tooltips appear on three controls only. | Sonnet lead | W7: the empty state and guided sequence in `main.ts`/`ui/`. |
| CP2.4 (#35, ADR 0007) | **`switchyard view`.** The CLI serves the built viewer from inside the binary (embedded assets, a localhost-only server) and opens the browser. W9: the CI and release steps that build the viewer before the CLI. |

**Gate:** visual QA screenshots (desktop and an 820 px narrow view), Lighthouse accessibility ≥ 90 on the local viewer, the release binary running `switchyard view` on Windows, macOS and Linux in CI, and one Opus review.

## Risks
| Risk | Mitigation |
|---|---|
| Report restructure breaks snapshot tests or the planted-suite graders, which parse report text | Graders read the Root-cause table and the `Interaction:` lines: keep those formats exactly, or update the graders in the same PR |
| `switchyard view` adds dependencies | Pure-Rust crates only (GNU toolchain rule); ADR 0007; localhost bind only |
| Design time creeps | Tokens-only pass; no new components beyond the headline card and collapsible sections |
| Actions minutes | The repo is public now (free); keep `paths-ignore` and `concurrency` anyway |
