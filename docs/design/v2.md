# Switchyard V2: design spec

**Plan:** [plans/v2.md](../plans/v2.md) · **Wireframes:** [wireframes/v2-wireframes.png](wireframes/v2-wireframes.png) (approve before any build) · **Research:** [2026-10-24-v2-design](../research/2026-10-24-v2-design.md) · **Last updated:** 2026-10-24

**Direction:** a serious engineering tool, in the spirit of an incident console crossed with a fleet dashboard. Dark, quiet and dense, with one accent. Colour carries meaning (state, fault, proof), never decoration. All values below go into `viewer/src/theme.ts` and the CSS custom properties that `applyThemeVars()` sets. No hard-coded colours anywhere else.

## Tokens

### Colour
The palette is based on the [Radix Colors](https://www.radix-ui.com/colors) dark scales (MIT).

| Token | Value | Use |
|---|---|---|
| `bg` | `#111113` (slate 1) | app background |
| `panel` | `#18191b` (slate 2) | sidebar and top bar |
| `panelRaised` | `#212225` (slate 3) | cards, inputs, buttons |
| `border` | `#272a2d` (slate 4) | hairlines |
| `borderStrong` | `#363a3f` (slate 6) | inputs, focused card |
| `text` | `#edeef0` (slate 12) | primary text |
| `textMuted` | `#b0b4ba` (slate 11) | labels, captions |
| `accent` | `#0090ff` (blue 9) | actual-throughput line, links, primary button, selection |
| `danger` | `#e5484d` (red 9) | failed robots, the incident band, the headline's cause |
| `warn` | `#ffc53d` (amber 9) | jammed or blocked chute, "within noise" |
| `ok` | `#30a46c` (green 9) | induction stations, "recovered" |
| `floor` | `#18191b` | floor cells |
| `gridLine` | `#212225` | grid |
| `chute` | `#ffc53d` at 70 % opacity | chutes (full opacity when jammed) |
| `twin` | `#b0b4ba`, dashed | the fault-free twin line |

Robot states (idle, to induction, loading, carrying, dropping, failed) are `#5b5f66`, `#0090ff`, `#8e4ec6`, `#edeef0`, `#f76b15` and `#e5484d`.

### Type
- **Font:** the system UI stack (`system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`). No web fonts: it runs offline from the binary.
- **Numbers:** `font-variant-numeric: tabular-nums`, everywhere a number can change.
- **Scale** (px): 12 caption · 13 body · 15 card title · 20 headline sentence · 32 headline number. Weights: 400 and 600 only.

### Space and shape
- **Spacing scale:** 4, 8, 12, 16, 24, 32 px. Card padding is 16; gaps between cards are 12.
- **Corner radius:** 6 px for cards, 4 px for controls. No shadows; borders only.
- **Sidebar** is 420 px wide; below 820 px it drops under the floor, as now.

## Components (only these are new or restyled)

### 1. Headline card (top of the Post-mortem tab)
```
┌────────────────────────────────────────────┐
│ INCIDENT 00:30–00:52 · 47 % below twin     │  12 px muted, caps
│                                            │
│ The C289 jam caused 70 % of the delay.     │  20 px, 600
│ Rerouting it to C269 would have saved 83 %.│  20 px, 400
│                                            │
│  6,264        110          83 %            │  32 px numbers
│  parcel-min   parcels late  recoverable     │  12 px muted
│                                            │
│ Proven by 96 replays · error bars from 8   │  12 px muted, with a
│ versions of the day · How we know ▸        │  link to Method
└────────────────────────────────────────────┘
```
- The cause word takes the `danger` colour and the fix takes `ok`.
- If the top two causes tie, the sentence reads "The C289 jam and the R119 failure each caused about 15 %; they're too close to rank."
- If the best fix is within noise, the second sentence is dropped.

### 2. Collapsible sections
Below the card, Summary and the top 3 causes stay open. Impact, all causes, Interactions, Fixes, Timeline and Method are collapsed. Each section is a header row with the title, a one-line teaser (for example "4 fixes tested · best 83 %") and a chevron. Use pure DOM with keyboard support (Enter/Space) and `aria-expanded`.

### 3. Chart
- The incident window gets a `danger` band at 12 % opacity.
- The area between the twin and the actual line inside the window is shaded `danger` at 20 %: that area is the loss.
- The twin's noise band is a light fill at 8 %.
- A single annotation marks the deepest point: "−47 %".
- Axis labels are 12 px muted; no gridlines except at 0 and the twin's mean.

### 4. Floor marks (CP2.2)
- **Failed robot:** a red ring that pulses at 1.2 s (respecting `prefers-reduced-motion`).
- **Jammed chute:** amber hatching.
- **Affected area:** a soft red glow under cells where blocked or yielded waits concentrated during the window, taken from the trace data.
- When the Post-mortem tab opens, the floor eases to frame the incident area in 400 ms.

### 5. First run (CP2.3)
- **Empty state** over the floor: "See an incident explained" and a primary button, **Load an incident**.
- The button loads the preset, plays at 8× to the end of the dip, pauses, and opens the Post-mortem tab.
- A three-step strip appears under the top bar (① Incident ② Trace a late parcel ③ Read the post-mortem) and is dismissible.
- Tooltips on three controls only: Speed, Inject fault and Analyse this run now.

## Don'ts
- No gradients, glassmorphism, emoji or icon packs. No more than one accent.
- No numbers on screen that don't come from the engine.
- Don't change the report's Root-cause table or `Interaction:` line formats; the test graders parse them (plan, Risks).

## Acceptance (visual QA)
- Desktop 1440×900 and narrow 820×1000 screenshots of the empty state, a mid-incident floor, and the Post-mortem tab with the card and collapsed sections.
- Contrast: text and controls meet WCAG AA, checked with Lighthouse accessibility ≥ 90.
- The 10-second test from the plan passes 3 of 3.
