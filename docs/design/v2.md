# Switchyard V2: design spec

**Plan:** [plans/v2.md](../plans/v2.md) · **Wireframes:** [wireframes/v2-wireframes.png](wireframes/v2-wireframes.png) (approve before any build) · **Research:** [2026-10-24-v2-design](../research/2026-10-24-v2-design.md) · **Last updated:** 2026-10-24

**Direction (CEO, 2026-10-24):** an **operations console in the spirit of Palantir's products**: dark, dense, data-first, built for an operator making decisions, not a demo. It should look like a senior team built it for a real client. We borrow the visual language, not the branding.

### Layout: a three-pane console with a timeline
```
┌ top bar: product · site/scenario · run controls · status chips ───────────────┐
├ left rail (240) ─┬ main canvas (floor) ──────────────────────┬ inspector (420) ┤
│ Incidents        │                                            │ selected object │
│ Faults (objects) │  floor + marks                             │ (incident card, │
│ Fixes tested     │                                            │  robot, chute,  │
│                  │                                            │  parcel)        │
├──────────────────┴ timeline (full width, 120): throughput vs baseline, incident band, fault spans ┤
└───────────────────────────────────────────────────────────────────────────────┘
```
- **Object-centric.** Everything is a clickable object: an incident, a fault, a robot, a chute, a parcel. Selecting one fills the inspector, and the floor and the timeline highlight it.
- **The timeline is the spine.** Throughput against the baseline, the incident band, and each fault as a horizontal span. Scrubbing it moves the floor.
- **Density with order:** small uppercase section labels, 1 px borders, 2 px radius, tabular and monospace numbers and IDs, no shadows and no gradients.

All values below go into `viewer/src/theme.ts` and the CSS custom properties set by `applyThemeVars()`; nothing is hard-coded elsewhere.

## Tokens

### Colour
Based on the [Blueprint](https://blueprintjs.com) dark palette (Palantir's open-source UI toolkit, Apache-2.0), so the look is authentic and licensed.

| Token | Value | Use |
|---|---|---|
| `bg` | `#1C2127` (dark gray 1) | app background |
| `panel` | `#252A31` (dark gray 2) | rails, top bar, timeline |
| `panelRaised` | `#2F343C` (dark gray 3) | cards, inputs, selected rows |
| `border` | `#383E47` (dark gray 4) | 1 px hairlines |
| `borderStrong` | `#404854` (dark gray 5) | focus, inputs |
| `text` | `#F6F7F9` (light gray 5) | primary text |
| `textMuted` | `#ABB3BF` (gray 4) | labels, captions |
| `accent` | `#2D72D2` (blue 3) | actual line, selection, primary button |
| `danger` | `#CD4246` (red 3) | failed robots, incident band, main cause |
| `warn` | `#C87619` (orange 3) | jammed or blocked chute, "within noise" |
| `ok` | `#238551` (green 3) | induction, recovered, the best fix |
| `twin` | `#ABB3BF`, dashed | the baseline (fault-free) line |

Robot-state colours keep the CP2 values, which pass the 3:1 contrast test (idle is `#64686f`), retuned to sit on `bg`.

### Type
- **Font:** the system UI stack for text; `ui-monospace, Consolas, monospace` for IDs, ticks and numbers in tables. Small labels are 11 px uppercase with 0.4 px tracking.
- **Text font:** the system UI stack (`system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`). No web fonts: it runs offline from the binary.
- **Numbers:** `font-variant-numeric: tabular-nums`, everywhere a number can change.
- **Scale** (px): 12 caption · 13 body · 15 card title · 20 headline sentence · 32 headline number. Weights: 400 and 600 only.

### Space and shape
- **Spacing scale:** 4, 8, 12, 16, 24, 32 px. Card padding is 16; gaps between cards are 12.
- **Corner radius:** 6 px for cards, 4 px for controls. No shadows; borders only.
- **Sidebar** is 420 px wide; below 820 px it drops under the floor, as now.

## Components (only these are new or restyled)

### 1. Headline card (top of the Post-mortem tab)
```
┌────────────────────────────────────────────┐
│ INCIDENT 00:30–00:52 · 47 % below twin     │  12 px muted, caps
│                                            │
│ The C289 jam caused 70 % of the delay.     │  20 px, 600
│ Rerouting it to C269 would have saved 83 %.│  20 px, 400
│                                            │
│  6,264        110          83 %            │  32 px numbers
│  parcel-min   parcels late  recoverable     │  12 px muted
│                                            │
│ Proven by 96 replays · error bars from 8   │  12 px muted, with a
│ versions of the day · How we know ▸        │  link to Method
└────────────────────────────────────────────┘
```
- The cause word takes the `danger` colour and the fix takes `ok`.
- If the top two causes tie, the sentence reads "The C289 jam and the R119 failure each caused about 15 %; they're too close to rank."
- If the best fix is within noise, the second sentence is dropped.

### 2. Collapsible sections
Below the card, Summary and the top 3 causes stay open. Impact, all causes, Interactions, Fixes, Timeline and Method are collapsed. Each section is a header row with the title, a one-line teaser (for example "4 fixes tested · best 83 %") and a chevron. Use pure DOM with keyboard support (Enter/Space) and `aria-expanded`.

### 3. Chart
- The incident window gets a `danger` band at 12 % opacity.
- The area between the twin and the actual line inside the window is shaded `danger` at 20 %: that area is the loss.
- The twin's noise band is a light fill at 8 %.
- A single annotation marks the deepest point: "−47 %".
- Axis labels are 12 px muted; no gridlines except at 0 and the twin's mean.

### 4. Floor marks (CP2.2)
- **Failed robot:** a red ring that pulses at 1.2 s (respecting `prefers-reduced-motion`).
- **Jammed chute:** amber hatching.
- **Affected area:** a soft red glow under cells where blocked or yielded waits concentrated during the window, taken from the trace data.
- When the Post-mortem tab opens, the floor eases to frame the incident area in 400 ms.

### 5. First run (CP2.3)
- **Empty state** over the floor: "See an incident explained" and a primary button, **Load an incident**.
- The button loads the preset, plays at 8× to the end of the dip, pauses, and opens the Post-mortem tab.
- A three-step strip appears under the top bar (① Incident ② Trace a late parcel ③ Read the post-mortem) and is dismissible.
- Tooltips on three controls only: Speed, Inject fault and Analyse this run now.


## Legibility: anyone can tell what's happening (CEO, 2026-10-24)
Someone glancing at the floor must understand it without reading docs. The long docs are for people who want the mechanics.
- **1× is real time:** 1 tick = 0.5 s, so 2 ticks per second. Speed steps are 1×, 4×, 16× and 64×. The guided demo starts at 4× and slows to 1× around the incident.
- **Smooth motion:** robots glide between cells (interpolated per frame) instead of jumping, so the eye can follow them.
- **Where it's going:** a carrying robot draws a thin, faint line to its destination chute, and its parcel is a dot inside it.
- **Faint trails** (the last ~5 cells) show the direction of flow; congestion reads as a dense cluster of short trails.
- **Focus mode:** selecting a robot, parcel or fault dims everything else to 25 % and draws that object's path and blockers.
- **Plain legend:** "carrying a parcel", "heading to pick up", "broken down", "chute", "pick-up station". No internal state names.
- **Hover labels:** robot id, what it's doing, where it's going, and how long it's been waiting.
- **Test:** a fresh viewer (Sonnet, given a 10-second clip) describes what's happening on the floor in one sentence: 3 of 3 right.

## Don'ts
- No gradients, glassmorphism, emoji or icon packs. No more than one accent.
- No numbers on screen that don't come from the engine.
- Don't change the report's Root-cause table or `Interaction:` line formats; the test graders parse them (plan, Risks).

## Acceptance (visual QA)
- Desktop 1440×900 and narrow 820×1000 screenshots of the empty state, a mid-incident floor, and the Post-mortem tab with the card and collapsed sections.
- Contrast: text and controls meet WCAG AA, checked with Lighthouse accessibility ≥ 90.
- The 10-second test from the plan passes 3 of 3.
