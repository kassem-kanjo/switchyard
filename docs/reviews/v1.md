# Switchyard v1: CEO review

**Date:** 2026-10-23 · **Tag:** v1.0.0 · **Prepared by:** Overseer

## In one paragraph
Switchyard treats a robot sortation hub like a distributed system. A deterministic twin of the floor traces every parcel. You can break the floor on purpose. The engine then writes the incident post-mortem: what caused the throughput drop, what each cause cost, and what would have fixed it. Every claim is proven by replaying the shift without that cause, and blame is split fairly with exact Shapley values and honest noise bands. V1 is the depth version: the engine, the algorithms and the proof. Design, UX and the launch are V2.

## Demo
- Viewer: `cd viewer && npm ci && npm run dev` (Node 22). Pick the preset "two-dead-robots-and-a-jam", then open Post-mortem.
- CLI: `cargo run --release -p switchyard-cli -- postmortem --help`.
- Screenshot: `docs/checkpoints/img/viewer-postmortem.png`.

## What's new since v0.1.0
- **CP1:** the floor sim and the viewer.
- **CP2:** parcel traces with causal blame chains, chaos injection, the fault-free twin.
- **CP3:** the post-mortem engine. It detects the incident (CUSUM), replays a checkpoint for every cause combination, computes exact Shapley attribution with per-mask noise bands, and tests candidate fixes. It produces an SRE-style report in the CLI and the viewer, and runs live in the browser for up to 4 faults.

## Risks and known gaps
- Small fault interactions sit inside the noise; the report hedges, but 11 of 48 are read wrong.
- The report is accurate but dense for an ops manager (the V2 headline card, #24, and the jargon fixes, #22).
- Not yet run: `cargo audit` (not installed). The panel has no DOM unit test.

## Insights for the thought pieces
`docs/insights.md`: identical faults aren't identical; intuition misjudges combined incidents; the floor hides how close to the edge it runs; averages invent "workarounds beat the root cause"; small interactions are unknowable.
